Page 1 / 2 · Process flow & inventory (L2–L3)

1 · Process mapping (L2)

  • Flow unit: item flowing through. Activity (□): takes time, uses resources. Buffer (△): waiting. Decision point (◇): routes flow.
  • Only resources have capacity & can be bottlenecks, never activities. Count every resource: workers, machines, tools (the handsaw trap: you 2 h + 1 h = 3 h is the bottleneck).
  • Map the process as it actually works; validate with the people involved.

2 · Flow time

Theoretical flow time = shortest time for one unit (perfect world, no waiting). Actual flow time can be longer.

Single path: sum of activity times. Simultaneous activities: longest path START→END.
  • A pooled activity (W1 or W2 does A) counts once.
  • Burger ∥ fries: 1+5+1+1+1 = 9 min, not 13. HW1 Q1: paths 18, 20, 20, 22.
  • Pooling or speeding a non-bottleneck task changes flow time, not capacity. A faster bottleneck task changes both.

3 · Unit load · capacity · bottleneck

Unit load (resource) = Σ times of all activities it does
Capacity = (# in pool) × 60 ÷ unit load (min) per hr
Process capacity = min over resources/pools = bottleneck
  • Unit load = 1 / capacity. Bottleneck = highest unit load per pool member. Ties are possible.
  • An activity needing 2 resources (Crane + Emp 1) adds its time to both unit loads.
  • Never compute capacity as 1 / flow time (McDonald's: 36 s ≠ 100/hr; real capacity 360/hr).
McDonald's: 8, 10, 8, 6, 2, 2 s → 450, 360, 450, 600, 1800, 1800 /hr
Flow time 36 s. 2nd cashier: still 360. 2nd toaster: 450, new bottlenecks cashier + W2. W3 does 6+2+2 = 10 s → still 360, frees W4, W5.

Improving capacity

  • (1) Pool the bottleneck (add copies). (2) Reduce its unit load: speed it up or reassign tasks.
  • Fixing one bottleneck can create another. Reduce only until it ties the next bottleneck; watch pools (Review SA2: worker 25 → 15 min, = 10 min).
  • Equipment caps capacity whatever the staffing (pizza oven: 1+10+1 = 12 s → max 5/min). Balancing work: 4.29 → 5/min, same 22 s of total work.

4 · Throughput & utilization

Throughput = min{input rate, capacity rate}
Utilization = throughput ÷ resource capacity (≤ 100%)
Implied util. = input ÷ resource capacity (can be > 100%)
Cycle time = 1 ÷ throughput
  • All utilizations < 100%: demand-limited. Some = 100%: that resource is the bottleneck, and input ≥ capacity.
  • Implied util. > 100% → inventory builds. Utilization is never > 100%.
  • Throughput = capacity does not imply build-up (input might equal capacity exactly).
  • Bottleneck has the highest utilization.

Profit decisions

Profit/hr = throughput × margin − hourly costs. Only adding capacity at the bottleneck helps; the new bottleneck caps the gain. Rev. SA1(e): rent 2nd B → cap 4/hr: $40 − $14 = $26 < $30, so don't rent. SA11(c): hire W3 → 8.57/hr: $85.7 − $60 = $25.7 > $20, so hire.

6 · Inventory build-up (L3)

  • Inventory in process = buffers + activities (pizza 3 + 1 + 1 = 5). Never < 0.
  • End-of-interval queue: Q = max{0, Qprev + input − capacity}.
  • Slope (build-up rate) = input − capacity while a queue exists. Output = capacity while queued, else = input.
  • When the queue drains, find when it hits 0 = Q ÷ (capacity − input).
Discrete avg = Σ snapshots ÷ # intervals
Continuous avg = area under curve ÷ total time
  • Split the area into triangles (½·b·h) and rectangles. A trapezoid = rectangle + triangle.
  • Same data, different methods: weeks 20 → 50: discrete (20+50)/2 = 35; continuous (10+20+15)/2 = 22.5.
  • Enough total capacity ≠ no queue (airport: 195 ≤ 240 yet queue peaks at 13; avg 51/16 = 3.19).
  • Stable: long-run input ≤ capacity. Short-run input can exceed it.

7 · Little's Law (L3)

I = R × T (avg inventory = throughput × avg flow time)
  • Requires stability. I, R, T must cover the same part of the process, in the same time units.
  • Rocks: R = 12/hr, T = 10 min = 1/6 hr → I = 2. I = 4 + 1 = 5, T = 20 min → R = 0.25/min.
  • BBA: 850 × 4 = 3400; 3500/4 = 875; 3600/800 = 4.5 yr. Queue: Tq = Iq/R = 75/87.5 h = 51.4 min.
  • Heathrow: count in/out → I, R → T = I/R (no need to match individuals). Uber: L − O = Y(η + T).

8 · Shouldice (L3 case)

  • Weekly capacity: beds 90 × 7/3 = 210; surgeons 12 × 4 × 5 = 240; ORs 5 × 8 × 5 = 200 (bottleneck). Daily: ≤ 90 beds, ≤ 48 surgeons, ≤ 40 ORs.
  • Now: R = 150/wk; I = 150 × 3/7 ≈ 64. Best Mon–Fri schedule: 40, 40, 10, 40, 40 = 170 (x₁ + (x₂+x₃+x₄) + x₅ ≤ 40 + 90 + 40). 180 needs Saturday surgery, +10 beds, or +1 OR.

9 · Scheduling: SPT & WSPT (L4)

Ci = Wi + pi ⇒ ΣC = ΣW + Σp (Σp fixed)
  • SPT: ascending pi → minimises ΣC and ΣW. Why: the 1st job's time appears in all n completion times.
  • WSPT: ascending pi/wi → minimises ΣwiCi and ΣwiWi.
  • Rank by ratio, but compute Ci by adding the actual pi. ΣwiWi = ΣwiCi − Σwipi.

10 · Variability

Same averages ≠ same queue. ATM (0.5/min, 1 min service): regular 0 wait; clustered arrivals 0.5 min; variable service 0.125 min. Flow time = waiting + service.

11 · Probability (L4)

E[X] = Σ xi·P(xi) · Var = E[(X − E[X])²]
σ = √Var · CV = σ / E[X] (no units)

1, 3, 5 items with prob .25/.5/.25 → E = 3, Var = 2, σ = 1.41, CV = 47.1%.

12 · Single-server queue (L4)

λ arrival rate; 1/λ = E[A]μ service rate; 1/μ = E[S]
ρ = λ/μ; stable iff ρ < 1; throughput = λ
PK: Iq ≈ ρ²/(1−ρ) × (CA² + CS²)/2
Tq = Iq/λ · Ts = 1/μ · Is = ρ
I = Iq + Is · T = Tq + Ts = I/λ
  • CA = SD(A)/E[A]; CS = SD(S)/E[S], using the times, in the same units.
  • Iq excludes the customer in service.
  • Alt. form: Iq ≈ λ²/[μ(μ−λ)] × (λ²σA² + μ²σS²)/2.

14 · Utilization vs variability · OM triangle

  • M/M/1 Iq at ρ = 50/80/90/95%: 0.5 / 3.2 / 8.1 / 18.05. 80→90% more than doubles it.
  • At ρ = 80%: exponential service 3.2 vs constant service 1.6.
  • No variability: max utilization is good. With variability: it's very bad (queues explode as ρ→1).
  • λ = 8: 6 min exp → 24 min wait; 5 min exp → 10 min; 6 min constant → 12 min. Target Iq 1.6: M/M/1 needs μ = 11.48, M/D/1 needs 10.
  • OM triangle: Capacity (capacity cost) · Inventory/buffer (waiting cost) · Information to cut variability, e.g. scheduling (improvement cost).

16 · Matching (L5, conceptual)

Platform decides when to match (now vs wait) and whom. Engagement comes from suspense and surprise → match similar skill. 1000/1400/1010/1390: match at once → gaps 400/380 (short wait); wait for 4 → gaps 10/10 (long wait, risk of quitting). Drawbacks: long queues for top players; win rate stuck near 50%.
